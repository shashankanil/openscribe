# Installation and everyday use

The first launch opens setup in its own 760×560 window: Welcome → Microphone → Connect → Works in every app → Try it → Meet the Flowbar, with four progress dots for the middle steps. Only the microphone and a speech key are required (`SetupReadiness.canDictate`); Accessibility is a separate, skippable step (`canPasteAnywhere`) because it is what lets OpenScribe paste into the focused app and watch shortcuts macOS otherwise reserves — lone modifiers and, from macOS 15, Option-only combinations including the default ⌥ Space. Skipping it keeps dictation in Notes (`pasteIntoFocusedApp = false`) and, when the Dictate shortcut needs the event tap, offers a one-tap switch to ⌃⌥ Space. Connect verifies the key with one small authenticated request before saving (`ProviderClient.verify`); a rejected key, an unreachable provider or an unclear answer is explained inline, with “Save anyway” for the last two. For OpenRouter, OpenAI and Groq the same key also becomes the cleanup and summary key when none exists. Try it uses the real global shortcut and checks off “Hold to talk, release to finish” and “Tap to go hands-free, tap again to finish”; a shortcut that can’t register is explained there with one-tap alternatives, and a Record button works without the keyboard. Return is the primary action and Esc goes back; Reduce Motion replaces the animated illustration with a still one.

Setup resumes from facts: the first missing requirement (microphone, then key); with both in place, Try it if the person reached it or Accessibility is already allowed, otherwise the Accessibility step. Closing the window is the way out and keeps progress. Once setup has been completed it never opens again by itself: a missing microphone or key shows a workspace banner with the fix and a Flowbar notice, and dictation or a meeting started without a key opens Settings › API & Models instead of setup. “Paste is off” appears as a banner when paste is switched on without Accessibility. `--onboarding` still forces the flow from the start.

Try-it recordings save to Notes and never paste into another app. The Done screen reveals the Flowbar, offers launch at login, and links to Meetings, Screenshots and Settings › AI & MCP (“Use your notes in AI”); sign-in is never part of setup. Cleanup remains optional, so a missing second provider key does not block first use. Keys remain scoped to the selected provider and endpoint.

The installer stages and verifies the signed bundle before replacing the existing app. A failed copy or verification leaves the existing installation intact. It requests administrator access only when the destination requires it, then launches setup through the logged-in user's workspace. A running OpenScribe must be closed before updating. Downloaded builds still need notarization for a completely frictionless Gatekeeper experience; local self-signing instructions are in the release notes.

The interface uses warm neutral surfaces, graphite text, and solid amber accents, with System, Light, and Dark appearances. Notes use a persistent library beside a dedicated editor, with titles, previews, date groups, search, pinning, autosave, and text export. New manual notes stay out of saved history until they contain text or a title. Original transcripts remain separately available and selectable. Meetings share the same controls and have separate summary, transcript, and recording tabs. Settings destinations live in the main sidebar, and Permissions is a status dashboard. Provider setup combines provider selection, API key, model, and advanced options in a single editor. Browsing or cancelling keeps the active connection unchanged; a connection activates only after its settings are saved successfully. Matching keys can be reused explicitly. Dictionary corrections, snippets, app styles, and vocabulary have focused add/edit forms with cancellation and save feedback.

Left-clicking the menu bar icon opens a quick panel with recording controls and recent notes that copy on click. Right-clicking keeps the native action menu. The nonactivating Flowbar has an elapsed timer, visible stop/cancel controls, processing feedback, and a brief saved confirmation. Starting dictation from the quick panel returns to the last external app; recording in the workspace saves to Notes without pasting into OpenScribe.

Launch at login uses macOS ServiceManagement and is available in Settings → General for packaged apps. The final onboarding step offers it enabled by default for new users. Pending system approval is shown in Settings. Configured login launches stay in the menu bar; after setup, missing requirements show a notice and a workspace banner instead of reopening onboarding.

Unreadable notes/settings files are backed up before new data can replace them. If the read or backup fails, writes to that file are blocked and the UI reports the problem. Failed saves do not show a successful autosave state. Clearing edited dictation preserves the empty edit and the original transcript separately. Older meetings receive defaults for later-added labels and options. Microphone startup and teardown translate AVFoundation Objective-C exceptions into recoverable errors, and global shortcuts are suspended while editing the shortcut.

Errors use a short, nonactivating bubble that disappears after six seconds. Technical service details are available on demand. Showing a notice never cancels recording or changes the capture phase. Meeting errors retain expandable details for later troubleshooting.

Meeting upload boundaries no longer define the reading layout. Consecutive text from each audio input forms paragraphs, with breaks for pauses and longer passages. Search and source filtering work on these passages. Original audio references remain available from timestamps and summary citations. Markdown exports use the same grouped text. Source labels are audio inputs, not speaker diarization; overlapping voices cannot be reliably ordered from coarse chunk timestamps alone.

## Design references

The notes library follows the permanent list-and-editor pattern in [Bear](https://bear.app/faq/hide-the-sidebar-and-note-list-on-mac-and-ipad/). The unified provider editor was informed by [MacWhisper’s provider setup](https://docs.macwhisper.com/article/58-setting-up-ai-providers-in-macwhisper), with one save action for the connection.

The focused setup and first-recording flow were informed by Wispr Flow's [setup guide](https://docs.wisprflow.ai/articles/3152211871-setup-guide) and [first dictation guide](https://docs.wisprflow.ai/articles/6409258247-starting-your-first-dictation). The meeting reader follows the emphasis on a coherent transcript and separate summary in its [meeting notes documentation](https://docs.wisprflow.ai/articles/9406970664-meeting-notes-and-the-editor-in-notetaker-beta). OpenScribe retains its own provider configuration and local recovery model.

## Verification

Automated checks cover the setup readiness split, onboarding resume rules, step order, key verification states against a stubbed provider (working, rejected, unexpected, unreachable, per-provider endpoint and header), the Accessibility-free fallback shortcut, every onboarding step rendered in light and dark (`/tmp/openscribe-ux-onboarding-<step>-<light|dark>.png`), Notes-only readiness, transcript grouping and source preservation, export consistency, and concise error text, alongside the existing capture/recovery/provider tests. A synthetic meeting reader is rendered using an isolated store; no user recording is created. The setup screens and sidebar controls are checked in the packaged dev app. Installer staging is exercised against a temporary destination with both a valid signed bundle and an invalid replacement.

A separately identified debug app was launched with an empty isolated profile and no onboarding argument: setup opened automatically, blocked continuation without a key, and resumed after skipping and relaunching. `OPENSCRIBE_TEST_PROFILE` redirects debug-build storage only; release builds always use the normal application data directory. macOS permission grants were not reset or accepted during verification. Gatekeeper behavior for downloaded, unnotarized releases remains subject to the installation instructions.

The UX overhaul passes 77 automated tests, including both-appearance rendering of the workspace, settings, onboarding and quick panel, unreadable-history backup and blocked writes, save retry, cleared dictation edits, empty manual drafts, connection draft isolation and validation, explicit key reuse, failed connection writes, legacy meeting decoding, and the audio exception bridge. Rendered previews are written to `/tmp/openscribe-ux-*.png`. A separate debug bundle and isolated profile are used for native UI checks. Native checks verify note autosave across navigation, provider browsing and cancellation, and the connection and personalization dialogs. Actual launch-at-login registration, hardware disconnects, and live provider recording still need verification with the installed app and its permissions.
